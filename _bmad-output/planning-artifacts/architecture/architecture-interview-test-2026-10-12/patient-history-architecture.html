Patient History Pipeline

Raw healthcare files become one gold table a doctor uses to review a single patient's history: every encounter, lab, diagnosis and medication, in date order, with exact service dates and no direct identifiers.

Shape

Three jobs that only talk through storage

Bronze, silver and gold are separate jobs. Each one reads the previous layer from Parquet, runs pure DataFrame transforms and overwrites its own folder. On EMR each job is one Step, and locally the same three functions run in sequence.

PHI boundary

Where each field is allowed to live

Every layer is PHI, gold included, because gold keeps full service dates for treatment use (45 CFR 164.506). Direct identifiers stop at silver/patients. That table never holds the patient key, so no MRN-to-key lookup table exists anywhere.

Decisions

The rules every story builds against

Six stories are built independently. These rules keep them compatible. The full contract, with what each rule prevents, is in ARCHITECTURE-SPINE.md.

AD-1 · AD-2

Storage is the only handoff

Parquet at {data_root}/{layer}/{source}/, overwritten each run, so reruns are safe. Local folder or S3, same code.

AD-3

Declared schemas, typed once

Every StructType lives in schemas.py. Bronze reads text only; silver parses dates. The day-of data swap edits this one module.

AD-4

Silver derives, gold selects

One helper owns the patient join, age and ZIP3. Events without a patient are dropped and counted. Gold only selects, unions and casts.

AD-5

One gold shape

Every event type passes through conform_to_gold, which fills missing columns with typed nulls and drops anything not in the gold schema.

AD-6 · AD-7

One key owner, fail fast

HMAC-SHA256 over facility:mrn, the only UDF. A missing key stops every job before Spark starts. The key never appears in step args, Spark config or logs.

AD-8

Counts, never values

Logs carry layer, source and row counts only. dropped = rows_in − rows_out covers invalid rows, duplicates and orphans.

Running it · AD-9, AD-10

One command, two targets

python -m pipeline run --target local

Runs bronze, silver and gold in sequence in one process. Tests and the demo use this.

python -m pipeline run --target emr

Prints the aws emr create-cluster command: a transient 7.14.0 cluster with three Steps that shuts down when gold finishes. Local versions are pinned to match the cluster.

Named, not built

Required in production

  • Care-team-only access to gold, with read audit logging
  • SSE-KMS encryption at rest for every layer and the EMR log bucket; TLS in transit
  • Signed AWS BAA and a HIPAA-eligible EMR configuration
  • Secrets Manager delivery of the HMAC key to EMR
  • Key rotation to patient_key_v2
Build order

A steel thread, cut from the end

Story 1 produces a working gold table by itself. Each later story adds one capability. If time runs short, cut from story 6 upward.
